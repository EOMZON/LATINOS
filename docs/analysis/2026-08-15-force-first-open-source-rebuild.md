# Latin Dance OS：以「发力」为首个核心专题的开源重构判断

## 结论

不再从“大而全的拉丁知识库”继续铺页面。保留现有 Latin Dance OS 的整体骨架，但把首个公开可验证产品收缩为：

> **让初学者看懂一个动作从哪里发力、力量如何经过身体、常见代偿是什么、接下来怎么练。**

网站承担入口与知识承接；`Force Lab / 发力实验室` 承担首个核心体验；现有动作反馈 demo 承担产品化验证；开源仓承担共创，但私有课堂原始转录不进入公开仓。

## 推荐的信息架构

首页只负责三个入口：

1. **今天练什么**：一个 3–10 分钟可执行 session。
2. **发力实验室**：首个核心入口，按动作或身体链查看“从哪里发力—如何传递—怎么自测”。
3. **Dance OS / Tools**：进入摄像头反馈、身体地图、节拍与其他 demo。

长期地图继续保留，但降低首页权重：

- Learn：学习路径
- Force：发力实验室（首发主线）
- Moves：动作与舞种知识图谱
- Practice：训练 session 与成长档案
- Library：经过版权筛选的外部资料
- Contribute：共创入口

## 开源共创模型

### 仓库边界

继续使用现有 `EOMZON/LATINOS`：

- `sites/frontdoor/`：正式入口
- `apps/demos/`：实验产品
- `content/force/`：建议新增，保存审核后的公开发力知识单元
- `docs/contributing/`：建议新增，保存贡献指南、审核标准、来源与媒体政策
- `private/`：不建议在该公开仓创建；私有 Minutes 保持仓外，仅通过不可逆摘要或私有 source id 建立来源链

### 两条贡献路径

程序贡献者：fork → feature branch → pull request → 自动测试 → review → merge。

非程序贡献者：使用 GitHub Issue 表单提交动作、体感、错误或资料线索；维护者审核后再转成结构化内容 PR。不要要求舞者先学 Git 才能共创。

### 必需治理文件

- `README.md`：一句话使命、当前重点、可运行方法、入口地图
- `CONTRIBUTING.md`：代码与内容两类贡献流程
- `CODE_OF_CONDUCT.md`
- `LICENSE`：代码许可证；内容和媒体许可证需单独说明
- `.github/ISSUE_TEMPLATE/`：动作知识、错误反馈、资料线索、功能建议
- `.github/pull_request_template.md`：来源、版权、专业审核、截图和测试
- `CODEOWNERS`：关键目录审核人

建议代码使用宽松开源许可证时，内容不要自动沿用同一许可证；课堂衍生内容、贡献文本、图片和视频必须逐类确认授权。正式选择许可证前需要一次独立版权判断。

## 分阶段重构

### Phase 0：证据闭环

- 完整归档 63 条评论并做主题编码。
- 将课堂 Minutes 只建立私有索引，不移动、不公开原文。
- 选 5 个最有代表性的发力问题。

完成标准：能展示“评论需求 → 私有课堂证据 → 公开知识卡”的可追溯关系。

### Phase 1：Force-first 可用切片

- 在现有 frontdoor 中新增 `/force`。
- 先做 5 张高质量发力卡，不做 100 篇文章。
- 每张卡包含身体链图、常见代偿、60 秒 drill、来源与审核状态。
- 首页把 Force Lab 升为主入口；旧站继续保留链接。

完成标准：一个重拾拉丁的用户能在 3 分钟内找到一个问题、看懂链路并开始练。

### Phase 2：共创试运行

- 补齐贡献协议、Issue 表单、PR 模板和自动校验。
- 邀请 3–5 位舞者/老师试提内容，不追求开放人数。
- 记录内容退回原因，迭代 schema 和审核门槛。

完成标准：至少 2 个外部贡献从提交到上线完整闭环，且没有来源或版权信息丢失。

### Phase 3：Preview 与域名决策

- 新 frontdoor 先发 preview。
- 做桌面/手机、构建、控制台、路由、可访问性检查。
- 再决定 `latindance.zondev.top` 是切新版首页，还是保留 v1 并把新版放到新路径/子域名。

完成标准：用户明确批准生产路径，且旧 proof 有可恢复入口。

## Best Minds 判断

### 问题本质

不是“怎样建一个更全面的网站”，而是“怎样把零散且私有的专业课堂经验，转成初学者能理解、能练、能纠错，又允许社区持续改进的公共产品”。

### 专家镜头（均为思想转述，不伪造引语）

- Don Norman：动作知识必须给出可感知的映射、反馈和错误恢复；身体链比抽象术语更接近用户理解。
- Kathy Sierra：用户不是为了浏览知识库，而是为了在真实能力上变得更好；首发应围绕一个可练会的能力闭环。
- Nadia Eghbal：开源不等于把仓库设为 public；贡献门槛、维护者负担、治理和可持续性决定社区能否存在。

### Top 1

先交付一个 **5 个主题的 Force Lab 垂直切片**，并同时建立可供非程序员参与的内容贡献流程。整体网站骨架保留，但暂不扩写其他模块。

### 对抗性测试

最强反方会说：

1. “发力”对初学者很吸引，但也是最容易伪科学、过度承诺和受伤的主题。
2. 只有你的课堂转录会形成单一老师/单一身体经验偏差。
3. 开源贡献会制造大量低质量、无来源、互相矛盾的动作建议，增加维护负担。
4. 如果只是把知识卡放上网页，仍然会落入“字典有用但没人看”的失败模式。

对应约束：

- 区分可观察动作、主观体感、教学提示、生物力学推断；不混成“科学事实”。
- 每条内容显示来源类型和审核状态，允许并列不同教学流派。
- 先邀请制试运行贡献，不一开始完全开放直接合并。
- 每张卡必须连到一个 drill 或互动工具，不交付纯阅读终点。

### 最小验证

选 5 个问题做成可点击原型，找 5 位目标用户完成：找到问题 → 看懂链路 → 跟练 60 秒 → 说出自己下一步应改什么。

成功标准：至少 4/5 用户无需解释完成路径，至少 3/5 能正确复述发力链和一个常见代偿；专业审阅者没有指出危险或明显误导。

停止条件：如果用户只收藏不练、无法复述链路，或专业审核持续否定核心内容，则暂停扩库，先修交互与内容模型。
