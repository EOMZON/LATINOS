# 飞书任务表主题标签语义审计

## 背景

目标表：

- `后续待处理的任务`
- `https://my.feishu.cn/wiki/XvKDwUWe7ibIDwkoTLzcPNBWnM3`

问题来自 LATINOS 记录只填写了：

- 分类：`产品设计`
- 子分类：`信息架构`

这两个字段能表达工作方式，却没有表达项目属于用户的重要人生主线：`拉丁`。

## 问题定义

跨主题任务总表必须同时回答两类不同问题：

1. 这件事属于哪个人生主题或长期项目？
2. 这件事采用什么工作类型和执行切面？

原表只有第二类字段，缺少第一类字段。

## 当前字段审计

现有相关字段：

- `分类`：单选，选项为游戏、域名 / 部署、信息架构、文案、代码、产品设计
- `子分类`：单选，选项为 DNS、Vercel、信息架构、SEO、内容、UI
- `任务性质`：单选，表达工程维护、需求任务、个人事务、远期想法、近期可执行等
- `母任务组`：单选，表达系统建设、内容创作、健康生活、研究想法等执行容器

这些字段都不能稳定表达：

- 拉丁
- 音乐
- 健康
- 求职
- AI / 系统
- 个人品牌等长期主题

## 样本证据

当前表中可见标题普遍使用项目前缀补偿语义缺口：

- `music_publish`
- `myObsidian`
- `zondev-monitor`
- `CODEXhelpME`
- `styles-atlas`
- `LATINOS`

这证明缺少主题轴不是 LATINOS 单条记录的问题，而是跨主题总表的结构性问题。

## 方案对比

### 方案 A：把“拉丁”加入分类

不推荐。

原因：

- `拉丁`是领域，`产品设计`是工作类型，两者不是同一维度
- 单选字段会迫使用户在“拉丁”和“产品设计”之间二选一
- 以后音乐、健康、求职也会与代码、文案、部署混在同一组选项中

### 方案 B：把“拉丁”加入子分类

不推荐。

原因：

- 子分类当前表达执行切面
- `拉丁`并不是产品设计下面的固定子类
- 同一个拉丁任务可能同时涉及 UI、内容、部署和代码

### 方案 C：新增多选字段“主题 / 人生主线”

推荐并已执行。

原因：

- 将领域主题与工作类型正交拆分
- 一个任务可以同时属于多个长期主题
- 可以直接按拉丁、音乐、健康等主题筛选和分组
- 不破坏现有分类体系和 2054 条历史记录

## 已执行

已在目标表新增：

- 字段：`主题 / 人生主线`
- 类型：多选

已为 LATINOS 记录新增并选择：

- `拉丁`

LATINOS 记录当前语义为：

- 主题 / 人生主线：`拉丁`
- 分类：`产品设计`
- 子分类：`信息架构`
- 任务性质：`近期可执行`
- 母任务组：`后续系统建设`

## 对其他表格的判断

不是所有表都需要同样字段：

- 单一领域专表已由表本身表达主题，例如只记录痛点、岗位或拉丁的表，不必重复主题
- 这张“后续待处理的任务”是跨领域总表，必须有独立主题轴
- 其他跨领域总表如果也只能靠标题前缀区分项目，就存在同类问题

当前只确认并修复了目标任务总表。没有在未审计的其他表中批量新增字段。

## 对抗性测试

### 风险：主题标签越来越多

控制方式：只允许稳定、长期、跨多条任务复用的主题进入该字段，不把临时功能词放进来。

### 风险：历史数据仍为空

控制方式：不一次性盲目回填 2054 条记录；先从当前活跃任务和明确标题前缀开始，小批量校正。

### 风险：主题与项目名混用

建议规则：

- 主题使用长期领域名，如拉丁、音乐、健康
- 项目名继续保留在标题、任务范围归属或未来独立项目字段
- `LATINOS` 是项目名，`拉丁` 是人生主题

## 结论

最佳结构不是让“拉丁”取代“产品设计”，而是同时保留两条语义轴：

`主题 / 人生主线 = 拉丁`

`分类 / 子分类 = 产品设计 / 信息架构`

## 下一步

1. 先观察新字段在活跃任务中的实际使用
2. 后续优先回填标题前缀非常明确的活跃任务
3. 再决定是否建立受控主题词表
4. 不对 2054 条历史记录做未经确认的全量自动分类
