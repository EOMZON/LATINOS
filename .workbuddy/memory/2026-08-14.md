## 2026-08-14 下午修复：首次启动 404 Not Found
- 现象：用户双击启动器后 app 窗口显示「404 Not Found」，但状态栏显示「本地内容已打开」，说明本地服务器已起、只是内容路径未命中。
- 根因：macOS 对 GUI app 访问 `~/Desktop/LATINOS/...` 存在 TCC/文件访问限制，导致 `StaticFileServer.resolveFileURL` 中 `fileExists` 返回 false，服务器回退 404。我之前的 Bash 内 standalone 测试有文件权限，所以没能复现。
- 修复（让 app 自包含，避免读源树）：
  - `scripts/package.sh` 增加 `cp -R "$CONTENT_ROOT/dist" "$RESOURCES_DIR/dist"`，把 dist 复制进 app bundle Resources。
  - `Sources/AppDelegate.swift` 把 `rootURL` 从硬编码源树路径改为 `Bundle.main.resourceURL!`，让 Swift 服务器从 bundle 内部读取。
- 验证（真实启动 app 后 probe 8917）：`GET /dist/`→200 text/html；`HEAD models/pose_landmarker_lite.task`→200；`GET wasm/vision_wasm_internal.wasm`→200 application/wasm。全部正常。
- 更新后注意：前端改完仍需在源项目跑 `npm run build`，然后重新跑 `bash scripts/package.sh` 把新 dist 打进 bundle；app 不再依赖源树路径存在。
